## O que já existe: definição dos módulos em context/modules/ (sem código)
## O que criar:
- Entidade User (id, email, name, avatarUrl, passwordHash, role: administrator|editor|member, emailVerifiedAt, status)
- Interfaces IUserRepository, IRefreshTokenRepository, IPasswordResetTokenRepository
- Use cases auth: Register, Login, RefreshToken (rotation), Logout, ForgotPassword, ResetPassword
- Use cases users: GetProfile, UpdateProfile, AssignRole, ListUsers, ActivateUser, DeactivateUser
- `IPasswordHasher` (bcrypt/argon2) + JWT próprio (access curto + refresh 7d rotation)
- Middleware verify-jwt (injeta userId + role)
- Route handlers Next.js (apps/web): /api/auth/register|login|refresh|logout|forgot-password|reset-password, /api/users/*
## Especificação:
- Senha nunca em claro — hash via IPasswordHasher no Register
- Refresh token com rotation e revogação (token antigo rejeitado)
- Rate limit em register (5 req/15min)
- Token de reset single-use (TTL 15min); reset revoga refresh tokens do usuário
- Papel padrão no registro: member
- `user.created`/`user.updated`/`password.reset`/`role.assigned` via EventBus
- Somente administrator gerencia papéis (AssignRole)
- Barrel export só público
## Critério de conclusão:
- [ ] Teste: refresh rotation (token antigo rejeitado)

- [ ] Teste: register com senha fraca rejeitado (Zod)
- [ ] Teste: somente administrator atribui papel
- [ ] verify-jwt nas rotas protegidas
- [ ] Barrel export atualizado
- [ ] Typecheck passando: `pnpm turbo typecheck --filter=@digimon/auth`
- [ ] Lint passando
